# وبلاگ یکپارچهٔ هادس

ساختار بخش فارسیِ نوشته‌ها و یادداشت‌های سایت بر پایهٔ قالب اصلی [Digital Garden](https://github.com/oleeskild/digitalgarden) است؛ افزونهٔ [Obsidian Digital Garden](https://github.com/oleeskild/obsidian-digital-garden) می‌تواند یادداشت‌ها را در همین مخزن منتشر کند.

- [وبلاگ، مقاله‌ها و یادداشت‌ها](https://ialirezaaa.github.io/fa/blog/)
- [یادداشت‌ها و مفاهیم](https://ialirezaaa.github.io/fa/blog/#notes)

تمام یادداشت‌های منتشرشده در `/fa/blog/notes/` قرار می‌گیرند. آدرس‌های محتوایی قدیمی `/fa/garden/` به بلاگ یا یادداشت متناظر هدایت می‌شوند؛ مسیر فایل‌های زیرساختی و تنظیمات اتصال Obsidian تغییر نمی‌کند.
- [منبع یادداشت‌ها](src/site/notes/)

## انتشار از Obsidian

در Obsidian، افزونهٔ **Digital Garden** را از Community plugins نصب و فعال کن. تنظیمات مقصد برای این سایت:

| تنظیم | مقدار |
| --- | --- |
| GitHub username | `iAlirezaaa` |
| Repository name | `iAlirezaaa.github.io` |
| Publish branch | `main` |
| Content base directory / Subfolder | `garden` |
| Garden URL / Base URL | `https://ialirezaaa.github.io/fa/garden/` |

توکن دسترسی را فقط در تنظیمات افزونهٔ روی دستگاه خودت وارد کن. توکن در سورس سایت یا فایل `.env` قرار نمی‌گیرد. بخش **Content base directory** به نسخه‌ای از افزونه نیاز دارد که انتشار داخل زیردایرکتوری را پشتیبانی می‌کند.

برای انتشار هر یادداشت، مشخصات ابتدای فایل می‌تواند این‌طور باشد:

```yaml
---
title: یادداشت من دربارهٔ تصویرسازی
dg-publish: true
aliases:
  - تصویرسازی
tags:
  - هوش-مصنوعی
---
```

بین یادداشت‌ها از `[[نام یادداشت]]`، `[[نام یادداشت|متن دلخواه]]` و `[[نام یادداشت#عنوان بخش]]` استفاده کن. سپس از Command Palette فرمان **Digital Garden: Publish Single Note** یا فرمان انتشار چند یادداشت را اجرا کن. تغییرات در GitHub ساخت نسخهٔ جدید سایت را فعال می‌کنند.

فقط صفحهٔ ورودی باغ باید `dg-home: true` داشته باشد؛ برای یادداشت‌های عادی این گزینه را اضافه نکن. یادداشت‌های بدون `dg-publish: true` وارد خروجی سایت نمی‌شوند. `public: false` و `draft: true` نیز انتشار را متوقف می‌کنند. مخزن حاضر عمومی است؛ فایل خصوصی را به خود مخزن عمومی اضافه نکن، حتی اگر قرار نیست در سایت نمایش داده شود.

## فارسی و مطالعه

صفحه‌ها و کنترل‌ها راست‌به‌چپ هستند. متن کد و نشانی‌ها جهت مستقل دارند. قلم اصلی **میخک** از خود سایت دریافت می‌شود؛ فایل اصلی و مجوز OFL در `src/site/fonts/` قرار دارند. جست‌وجو برای «ی/ي»، «ک/ك»، رقم‌های فارسی و نیم‌فاصله نرمال‌سازی می‌شود. تاریخ‌ها شمسی نمایش داده می‌شوند.

فهرست پوشه‌ها، جست‌وجو، پیش‌نمایش پیوندها، گراف محلی و کلی، پیوندهای ورودی، فهرست مطالب و تنظیمات مطالعه در مقاله‌ها و یادداشت‌ها از یک پوسته استفاده می‌کنند. روی موبایل، فهرست و اطلاعات صفحه از دکمه‌های جدا باز می‌شوند.

## ساخت سایت و نگهداری

```sh
npm ci --prefix site
npm ci --prefix garden
npm --prefix site run build
node site/scripts/postbuild.mjs
node site/scripts/verify-blog-garden.mjs
node site/scripts/validate-site.mjs
```

منبع قابل ویرایش یادداشت‌ها `garden/src/site/notes/` است. منبع مقاله‌های فعلی `site/public/fa/blog/entries.js` باقی می‌ماند و هنگام ساخت به قالب باغ وارد می‌شود. مسیرهای مقاله‌ها، دسته‌بندی‌ها، برچسب‌ها و تصاویر قبلی حفظ شده‌اند. فایل‌های `fa/` در ریشهٔ مخزن خروجی انتشار هستند؛ آنها را دستی ویرایش نکن.

فایل `garden.config.json` تنظیمات پیش‌فرض فارسی را نگه می‌دارد. `.env` فقط برای تنظیمات عمومی ظاهر است و افزونه می‌تواند آن را به‌روزرسانی کند. ساخت ابتدا یادداشت‌های مجاز را در پوشه‌ای موقت جدا می‌کند و بعد قالب Eleventy را اجرا می‌کند. هیچ یادداشت مرتبطی صرفاً به دلیل پیوندخوردن خودکار منتشر نمی‌شود.

پوستهٔ فارسی در فایل‌های `src/site/_includes/components/hades*`، استایل اختصاصی و `src/site/scripts/hades.js` نگهداری می‌شود. هنگام به‌روزرسانی قالب اصلی، تغییرات را در pull request بررسی و همین آزمون‌ها را اجرا کن.

این راهنما مقصد انتشار را آماده می‌کند. اتصال Obsidian روی دستگاه مالک باید در خود افزونه انجام شود؛ این مخزن حاوی هیچ توکن اتصال نیست.

## سازگاری قابلیت‌های اصلی Digital Garden — بدون بازطراحی

مبنای تطبیق: [فهرست رسمی قابلیت‌های افزونه](https://github.com/oleeskild/obsidian-digital-garden#features) و [قالب Eleventy](https://github.com/oleeskild/digitalgarden). پوستهٔ HADES، امکانات فعلی مطالعه و مسیرهای canonical تغییر نمی‌کنند. کامنت، لایک، دیسلایک، امتیازدهی و سرویس‌های اجتماعی اضافه نمی‌شوند.

- Markdown، لینک‌های ویکی/نسبی، callout، footnote، highlight، code، MathJax و PlantUML در موتور اصلی موجودند؛ قالب سفارشی مسیر ورودی را صریحاً به resolver می‌دهد.
- Mermaid: بارگذاری نسخهٔ ثابت فقط در صفحات دارای نمودار، strict mode و نمایش متن در صورت خطای شبکه یا نمودار. PlantUML همچنان به مسیر رندر upstream وابسته است. Mermaid و PlantUML با شبکهٔ قطع‌شده تضمین نشده‌اند.
- Bases: CSS مخصوص کامپوننت upstream، موتور query و view-switcher موجود؛ فایل‌های تصویرِ صریحاً ارجاع‌شده در property یادداشت مجاز به مرحلهٔ ساخت منتقل می‌شوند. تصویر مبهم و symlink منتقل نمی‌شوند. PDF/image/HTML asset با مسیر صریح /img/user/ از یادداشت مجاز منتقل می‌شود.
- Canvas و Excalidraw: فایل‌های کامپایل‌شدهٔ افزونه و runtimeهای موجود حفظ می‌شوند؛ CSS فقط داخل Canvas و دیگر کامپوننت‌های محتوایی لازم بارگذاری می‌شود، نه تم اصلی. Canvas خام JSON مستقیماً قابل انتشار نیست؛ افزونه Obsidian آن را کامپایل می‌کند.
- Dataview / DataviewJS، ترنسکلود یادداشت و بخش/بلوک، SVG، Excalidraw، فایل‌های PDF و فیلترهای regex سفارشی در زمان انتشار در خود افزونهٔ Obsidian کامپایل می‌شوند؛ نیاز به نصب/اجرای واقعی افزونه روی دستگاه مالک دارند. اجرای JavaScript دلخواه Dataview در مرورگر عمومی فعال نمی‌شود. یادداشت‌های خصوصی/پیش‌نویس هرگز خودکار به stage وارد نمی‌شوند؛ مالک نباید محتوای خصوصی را داخل یادداشت عمومی transclude کند.
- جست‌وجو، پیش‌نمایش پیوند، filetree، backlinks، گراف کلی و محلی موجود؛ عمق ۱ تا ۳ گراف محلی با تنظیم موجود dgShowGraphDepthControl فعال می‌شود. هیچ مسیر عمومی موازی Garden اضافه نشده است.
- تنظیمات تم Obsidian/Style Settings و تغییر آیکون‌ها/پوسته عمداً اعمال نشده‌اند (درخواست مالک: طراحی ثابت). از Vercel/Netlify/Forestry هم استفاده نمی‌شود؛ GitHub Pages فعلی حفظ شده است.

آزمون اتصال واقعی افزونهٔ Obsidian و نمونه‌های محتوایی کامل از vault مالک، رندر زندهٔ Mermaid/PlantUML با شبکه، Canvas/Bases/Excalidraw روی دستگاه واقعی، و HTTP پس از deploy تا ثبت شواهد جداگانه OPEN هستند.

## دیدگاه‌های عمومی وبلاگ — 2026-11-25

به درخواست مالک، فقط کامنت فعال می‌شود؛ هیچ لایک، دیسلایک، امتیازدهی یا نظرسنجی به رابط اضافه نمی‌شود. GitHub Discussions در زمان تنظیم غیرفعال بود و Issues فعال بود. برای هر مقاله/یادداشت عمومی موجود یک Issue مستقل با نشانگر canonical ساخته شده است. جدول مسیر به شمارهٔ Issue در `src/site/_data/blogComments.json` قرار دارد. برای نوشته‌های جدید ابتدا Issue متناظر با نشانگر `<!-- hades-blog-comments:/fa/blog/.../ -->` ایجاد و شماره را در این جدول ثبت کن؛ از ساخت تکراری خودداری کن. صفحات فهرست، خصوصی و aliasها بخش دیدگاه ندارند. متن نظرات با درخواست صریح بازدیدکننده از GitHub API خوانده و به‌صورت متن امن نمایش داده می‌شود. ثبت دیدگاه با ورود به GitHub و پیوند همان Issue انجام می‌شود؛ هیچ توکن یا سرور نوشتن در سایت نیست. مدیریت و حذف نظرات از Issues صورت می‌گیرد. برای ثبت مستقیم درون ویجت می‌توان پس از مجوز مالک، [Utterances](https://github.com/apps/utterances) را فقط روی مخزن عمومی سایت نصب کرد؛ نصب/احراز هویت و تست ارسال نظر واقعی از درون ویجت هنوز OPEN است. نمونه‌های مصنوعی آزمون هیچ‌گاه در GitHub Issues ارسال نمی‌شوند.

## نقشهٔ قابل جابه‌جایی و رابط خلوت‌تر

نودهای گراف با ماوس یا لمس کشیده می‌شوند؛ روی نود فوکوس‌شده، کلید جهت‌نما آن را جابه‌جا می‌کند و Enter نوشته را باز می‌کند. خط‌های ارتباط و برچسب‌ها همزمان به‌روز می‌شوند؛ کشیدن نباید باعث باز شدن لینک شود. هنگام تغییر ابعاد، مختصات نرمال‌شده و دوربین حفظ می‌شوند؛ بازنشانی گراف موقعیت اولیه را بازمی‌گرداند. تنظیمات دقیق جابه‌جایی داخل تنظیمات نقشه قرار دارند. رابط اصلی به یک کاوشگر، یک نوار ابزار دسکتاپ و فهرست فشردهٔ مقاله/یادداشت محدود شده؛ موضوع‌ها، دسته‌ها، فیلتر و محتوای کامل همچنان در مسیرهای قبلی موجودند. پنل تاریخچهٔ اخیر فقط هنگام وجود سابقه نمایش داده می‌شود. هیچ قابلیت اجتماعی جدیدی اضافه نشده است. آزمون واقعی ماوس، لمس و تغییر اندازه/انتشار عمومی تا نتیجهٔ CI و HTTP مستقل OPEN است.
